# GitLab CI/CD Variables Configuration

This document outlines the required variables that need to be configured in your GitLab project's CI/CD settings.

## Required Variables

### Docker Registry Variables
These are automatically provided by GitLab:
- `CI_REGISTRY` - GitLab's container registry URL
- `CI_REGISTRY_USER` - Registry username
- `CI_REGISTRY_PASSWORD` - Registry password
- `CI_REGISTRY_IMAGE` - Full image name for the project

### Staging Environment Variables
Configure these in GitLab CI/CD Variables (Settings > CI/CD > Variables):

| Variable Name | Description | Example |
|---------------|-------------|---------|
| `STAGING_HOST` | Staging server hostname/IP | `staging.example.com` |
| `STAGING_USER` | SSH username for staging server | `deploy` |
| `STAGING_SSH_PRIVATE_KEY` | Private SSH key for staging server | `-----BEGIN OPENSSH PRIVATE KEY-----...` |
| `STAGING_PATH` | Application path on staging server | `/var/www/studio-5` |

### Production Environment Variables

| Variable Name | Description | Example |
|---------------|-------------|---------|
| `PRODUCTION_HOST` | Production server hostname/IP | `prod.example.com` |
| `PRODUCTION_USER` | SSH username for production server | `deploy` |
| `PRODUCTION_SSH_PRIVATE_KEY` | Private SSH key for production server | `-----BEGIN OPENSSH PRIVATE KEY-----...` |
| `PRODUCTION_PATH` | Application path on production server | `/var/www/studio-5` |

### Application Environment Variables
These should be configured for each environment:

| Variable Name | Description | Required |
|---------------|-------------|----------|
| `DATABASE_URL` | PostgreSQL connection string | Yes |
| `MINIO_ENDPOINT` | MinIO server endpoint | Yes |
| `MINIO_PORT` | MinIO server port | Yes |
| `MINIO_ACCESS_KEY` | MinIO access key | Yes |
| `MINIO_SECRET_KEY` | MinIO secret key | Yes |
| `MINIO_BUCKET_NAME` | MinIO bucket name | Yes |
| `NEXTAUTH_URL` | NextAuth.js URL | Yes |
| `NEXTAUTH_SECRET` | NextAuth.js secret | Yes |
| `AZURE_AD_CLIENT_ID` | Azure AD client ID | No |
| `AZURE_AD_CLIENT_SECRET` | Azure AD client secret | No |
| `AZURE_AD_TENANT_ID` | Azure AD tenant ID | No |
| `GOOGLE_API_KEY` | Google API key | No |
| `PROCESSOR_API_KEY` | Processor API key | Yes |

## Security Considerations

1. **SSH Keys**: Store SSH private keys as file variables in GitLab CI/CD settings
2. **Secrets**: Mark sensitive variables as "Protected" and "Masked"
3. **Environment Variables**: Use different values for staging and production
4. **Access Control**: Limit who can access production deployment variables

## Setup Instructions

1. Go to your GitLab project
2. Navigate to Settings > CI/CD > Variables
3. Add each variable listed above
4. Mark sensitive variables as "Protected" and "Masked"
5. Ensure the variables are available for the appropriate environments

## Branch Protection

Configure branch protection rules:
- Require pipeline to succeed before merging
- Require approval from code owners
- Restrict force pushes to protected branches

## Environment Configuration

### Staging Environment
- Branch: `develop`
- URL: `https://staging.studio-5.com`
- Auto-deploy on push to develop branch

### Production Environment
- Branch: `main` or `master`
- URL: `https://studio-5.com`
- Manual deployment with approval

## Troubleshooting

### Common Issues

1. **Docker Build Failures**
   - Check Dockerfile syntax
   - Verify all required files are present
   - Check for missing dependencies

2. **Deployment Failures**
   - Verify SSH keys are correct
   - Check server connectivity
   - Ensure target directories exist

3. **Environment Variable Issues**
   - Verify all required variables are set
   - Check variable names match exactly
   - Ensure variables are not masked incorrectly

### Debug Commands

```bash
# Test SSH connection
ssh -i /path/to/key user@host

# Check Docker registry access

# Verify environment variables
``` 
