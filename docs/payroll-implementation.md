# Payroll implementation

## Current-state assessment

Before this implementation, all five Payroll navigation destinations rendered `ComingSoonPage`. The repository already contained basic `PayrollPeriod`, `PayrollRun`, `PayrollRunItem`, `Payslip`, `CompensationPackage`, `BenefitPlan`, `EmployeeBenefitEnrollment`, and `PayrollAdjustment` models, plus a later HRIS foundation migration that added company scope, version fields, rule sets, exceptions, exports, compensation reviews, and benefit metadata. A draft, explicitly non-authoritative Thailand calculation engine and two `/api/payroll/v1` endpoints also existed.

The existing foundation was useful but incomplete: there was no Payroll workspace service, no employee payroll profile or pay-group model, no stored calculation lines or input snapshots, no variance/approval/payment/accounting/reconciliation records, no usable frontend, and no connection from Payroll to approved attendance, leave, expenses, compensation, or benefits. Prisma's declared models also lagged the raw-SQL foundation migration, so Payroll v1 already depended on defensive raw SQL.

Existing platform infrastructure is reused:

- `hr_employees` remains the employee, company, client, bank, tax, manager, and organization source of truth.
- Approved attendance, leave, and Expenses records are consumed by reference; Payroll does not own or duplicate those workflows.
- `NotificationService` supplies in-app notifications and deep links.
- `logAudit` supplies immutable application audit entries.
- `resolveCompanyScope` and backend permission checks enforce company isolation.
- The existing object/file-storage and employee-document patterns remain the integration point for durable PDF artifacts.

## Gap analysis and implementation decisions

| Area | Previous gap | Implementation |
| --- | --- | --- |
| Navigation | Payroll had placeholders and an extra Payslips sidebar entry | Preserve exactly Payroll, Payroll Runs, Compensation, Benefits, and Reports; payslips remain internal/ESS functionality |
| Tenant safety | Partial company scope in v1 runs only | Resolve actor company on every workspace request and constrain every query/mutation server-side |
| Payroll setup | No pay groups or payroll profiles | Effective operational pay groups and versioned employee payroll profiles |
| Inputs | No traceable input ledger | Source-linked, approval-aware payroll inputs with idempotency keys |
| Calculation | Preview only | Deterministic server calculation, stored input/output snapshots, calculation lines, versions, and exceptions |
| Workflow | Five coarse statuses | Controlled draft-to-close workflow, four-eyes approval, optimistic version checks, finalization lock |
| Review | No variance or exception UX | Stored exceptions and previous-period variance records with materiality thresholds |
| Outputs | Minimal payslip row only | Payslip release records, payment batches, balanced journal lines, reconciliation records, and export audit |
| Compensation | Base salary only | Effective-dated packages and controlled change requests with before/after values |
| Benefits | Plans and enrollment only | Eligibility/contribution metadata and payroll-linked deductions |
| Reporting | No reports | Company-scoped operational registers and authorized CSV export endpoints |

## Information architecture

- **Payroll**: command center, readiness, employee setup, current period, integrations, exceptions.
- **Payroll Runs**: run list and guided processing context for population, inputs, calculation, review, approval, finalization, payments, accounting, and reconciliation.
- **Compensation**: current packages, pending changes, effective dates, comparison, history.
- **Benefits**: plans, eligibility, enrollments, contributions, dependents, payroll impact.
- **Reports**: payroll, payment, accounting, compensation, benefits, audit, and exports.
- **Payslips**: generated by finalized Payroll Runs and released through secure employee documents/ESS; not a sixth sidebar module.

## Calculation and security assumptions

- Currency amounts are stored at two-decimal precision and calculation inputs are snapshotted.
- Country rules are versioned plug-ins. The bundled Thailand rules remain marked draft and non-authoritative until a qualified reviewer approves a rule set in the database.
- Finalized and closed runs are immutable. Corrections use off-cycle, amendment, retroactive, final, or reversal runs.
- Bank, tax, and payment values are masked in list responses. Unmasked exports require Payroll management permission and are audited.
- A non-admin user is constrained to the company on their employee record. Employee payslip access additionally requires matching employee ownership and released status.

## Migration and setup

Run the normal migration command:

```sh
npx prisma migrate deploy
```

The migration is additive and backward-compatible. Existing payroll rows are preserved and new workflow columns receive safe defaults.

## Remaining external dependencies

Production statutory formulas, bank-file layouts, government submissions, accounting-provider delivery, cryptographic PDF signing, and live bank responses require approved country/provider specifications and credentials. The module stores versioned rules and provider-neutral output records so those integrations can be added without changing historical payroll.
