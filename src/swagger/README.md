# Swagger Documentation Structure

This directory contains the modular OpenAPI 3.0 specification for the Studio API.

## Structure

```
src/swagger/
├── README.md           # This file
├── index.ts           # Main entry point that combines all modules
├── base.ts            # Base OpenAPI configuration (info, servers, security, tags)
├── schemas.ts         # All data models and schemas
└── paths/             # API endpoint definitions organized by feature
    ├── auth.ts        # Authentication endpoints
    ├── candidates.ts  # Candidate management endpoints
    ├── positions.ts   # Position management endpoints
    ├── users.ts       # User management endpoints
    ├── notifications.ts # Notification endpoints
    ├── dashboard.ts   # Dashboard endpoints
    ├── health.ts      # Health check endpoints
    └── upload-queue.ts # Upload queue endpoints
```

## Benefits of Modular Structure

1. **Maintainability**: Each feature area has its own file, making it easier to find and update specific endpoints
2. **Reusability**: Schemas and base configuration can be reused across different path modules
3. **Performance**: Smaller files load faster and are easier to cache
4. **Collaboration**: Multiple developers can work on different API sections without conflicts
5. **Testing**: Individual modules can be tested in isolation

## Migration from Monolithic File

The original `src/swagger.ts` file (164KB, 3782 lines) has been replaced with this modular structure. The original file is backed up as `src/swagger.ts.backup`.

## Usage

The API documentation is automatically generated by combining all modules:

```typescript
import { getSwaggerSpec } from '@/swagger/index';

// Returns the complete OpenAPI specification
const spec = getSwaggerSpec();
```

## Adding New Endpoints

1. Identify the appropriate path module (e.g., `candidates.ts` for candidate-related endpoints)
2. Add the endpoint definition to the existing paths object
3. Import and include the path module in `index.ts` if it's a new module

## Schema References

When referencing schemas in path definitions, use the `$ref` syntax:

```typescript
{
  schema: { $ref: '#/components/schemas/Candidate' }
}
```

## Backward Compatibility

The old `src/swagger.ts` file still exists as a thin wrapper that imports from the new modular structure, ensuring backward compatibility for any existing imports.
